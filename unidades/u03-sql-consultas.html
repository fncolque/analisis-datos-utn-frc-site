Qué es SQL

SQL, Structured Query Language, es un lenguaje para trabajar con datos organizados en relaciones. En una base relacional, una relación se representa habitualmente como una tabla: cada fila describe una observación y cada columna expresa un atributo con un tipo definido.

SQL es declarativo. La consulta describe el resultado buscado y el motor elige un plan de ejecución. Por ejemplo, una persona puede pedir la venta neta por familia mediante SELECT, SUM y GROUP BY; el motor decide cómo leer, filtrar y agregar los datos disponibles.

El lenguaje aparece en sistemas transaccionales, data warehouses, herramientas de Business Intelligence, procesos ETL o ELT y notebooks analíticos. La sintaxis cambia en algunos detalles entre DuckDB, PostgreSQL, BigQuery, SQL Server, Snowflake y otros motores. El modelo mental central se mantiene: fuentes, filas, columnas, relaciones, tipos y operaciones sobre conjuntos.

Qué objetos encuentra una consulta

Una consulta puede leer distintos objetos del catálogo:

  • una tabla conserva datos y una definición de columnas;
  • una vista conserva una consulta con un nombre reutilizable;
  • una tabla temporal vive durante una sesión y sirve para cálculos intermedios;
  • una CTE da nombre a un resultado dentro de una consulta;
  • una subconsulta produce una relación que otra consulta puede consumir.

En Faro Sur se comienza con vw_ventas. Esa vista ya reúne campos de pedidos, clientes, productos y líneas. Su grano es la línea de pedido: una fila representa un producto incluido en un pedido.

La clasificación siguiente ayuda a reconocer el alcance de una sentencia. Algunos manuales agrupan SELECT dentro de DML; en docencia también se usa DQL para distinguir la consulta de la modificación.

El entorno de práctica

Los notebooks usan DuckDB. El motor puede consultar archivos CSV desde una sesión local y devolver resultados tabulares. Esta elección reduce configuración y conserva una experiencia SQL cercana a sistemas de bases relacionales mayores.

El Paquete B crea una vista sobre el archivo preparado:

CREATE OR REPLACE VIEW vw_ventas AS
SELECT *
FROM read_csv_auto(
    'datos/vw_ventas.csv',
    header = true
);

CREATE OR REPLACE VIEW pertenece a DDL. La sentencia registra un nombre y una definición de consulta. En cada ejecución posterior, SELECT usa esa definición para acceder a los datos.

De la pregunta de negocio al contrato de consulta

Antes de escribir SQL conviene declarar siete elementos:

  1. decisión: qué uso tendrá el resultado;
  2. unidad: qué representa una fila de la fuente;
  3. métrica: qué se medirá;
  4. dimensión: cómo se dividirá el resultado;
  5. población: qué filtros delimitan los casos;
  6. orden: cómo se facilitará la comparación;
  7. control: qué total o conteo debe reconciliar.

Pregunta de ejemplo:

¿Qué familias explican la venta neta de Patagonia durante los meses disponibles de 2026?

El contrato queda definido así:

  • unidad de entrada: línea de pedido;
  • métrica: suma de venta_neta;
  • dimensión: familia;
  • población: Patagonia, desde 2026-01-01 hasta el límite exclusivo 2026-08-01;
  • orden: venta neta descendente;
  • control: total de Patagonia para el mismo período.

Primera consulta: SELECT, FROM y LIMIT

SELECT declara las columnas del resultado. FROM identifica la fuente. LIMIT restringe la cantidad de filas mostradas.

SELECT
    fecha_pedido,
    pedido,
    cliente,
    producto,
    venta_neta
FROM vw_ventas
LIMIT 5;

Esta consulta sirve para reconocer nombres, valores y grano. LIMIT cambia la salida visible y deja intacta la fuente.

SELECT * permite una inspección breve. Una consulta documentada declara columnas explícitas para exponer intención, estabilizar el esquema de salida y limitar transferencia innecesaria.

Alias y expresiones

Una columna de salida puede calcularse a partir de otras columnas. AS asigna un nombre legible al resultado.

SELECT
    pedido,
    producto,
    cantidad,
    precio_unitario,
    descuento_pct,
    cantidad * precio_unitario AS venta_bruta_calculada,
    cantidad * precio_unitario * (1 - descuento_pct)
        AS venta_neta_calculada
FROM vw_ventas
LIMIT 5;

La expresión revela la regla de negocio. También permite comparar venta_neta_calculada con la columna publicada y detectar diferencias de fórmula o redondeo.

WHERE: definir la población

WHERE conserva las filas cuya condición resulta verdadera. Los operadores frecuentes incluyen:

  • comparación: =, <>, >, <, >=, <=;
  • pertenencia: IN;
  • rango: BETWEEN;
  • patrón de texto: LIKE;
  • composición lógica: AND, OR, NOT.
SELECT
    pedido,
    cliente,
    familia,
    venta_neta
FROM vw_ventas
WHERE region = 'Patagonia'
  AND familia IN ('Bombas', 'Repuestos')
  AND venta_neta >= 5000
ORDER BY venta_neta DESC
LIMIT 10;

Los paréntesis vuelven explícita la precedencia cuando se combinan AND y OR:

WHERE region = 'Norte'
  AND (
      familia = 'Bombas'
      OR familia = 'Repuestos'
  )

Cada filtro modifica el universo. La documentación debe conservar las condiciones aplicadas y el motivo de cada una.

Fechas y límites de período

La fecha elegida debe corresponder al evento de la pregunta. fecha_pedido mide demanda registrada. Una futura fecha_prometida mediría compromiso y una fecha_entrega mediría ejecución logística.

Para períodos consecutivos conviene usar un límite inferior inclusivo y un límite superior exclusivo:

WHERE fecha_pedido >= DATE '2026-01-01'
  AND fecha_pedido <  DATE '2026-08-01'

Este patrón sigue funcionando si el campo incorpora hora. También evita decidir manualmente cuál es el último instante de un mes.

ORDER BY y determinismo de la salida

ORDER BY organiza las filas del resultado. ASC indica orden ascendente y DESC descendente.

SELECT
    pedido,
    producto,
    cantidad,

FROM vw_ventas
ORDER BY venta_neta DESC, pedido ASC
LIMIT 5;

NULL y lógica de tres valores

NULL representa un valor ausente o desconocido. La comparación se expresa con IS NULL o IS NOT NULL:

SELECT COUNT(*) AS filas_sin_region
FROM vw_ventas
WHERE region IS NULL;

Expresiones como region = NULL producen un valor desconocido y quedan fuera del filtro. Las agregaciones suelen omitir valores NULL de la columna agregada. COUNT(*) cuenta filas; COUNT(region) cuenta valores presentes.

COALESCE(region, 'Sin clasificar') reemplaza el valor en la salida. Esa decisión reúne casos distintos bajo una etiqueta y requiere una regla de negocio explícita.

Conteos y DISTINCT

SELECT
    COUNT(*) AS lineas,
    COUNT(DISTINCT pedido) AS pedidos,
    COUNT(DISTINCT cliente) AS clientes
FROM vw_ventas;
lineas pedidos clientes
75003574120

DISTINCT elimina duplicados del conjunto seleccionado. Aplicarlo sobre pedido produce pedidos únicos. Aplicarlo sobre pedido, familia produce combinaciones únicas. La lista de columnas define qué significa duplicado.

Agregaciones y métricas aditivas

Las funciones de agregación resumen varias filas:

  • SUM calcula un total;
  • COUNT calcula una cantidad;
  • AVG calcula un promedio simple;
  • MIN y MAX identifican extremos.

El total del release se obtiene con:

SELECT
    ROUND(SUM(venta_neta), 2) AS ventas_netas_usd,
    ROUND(SUM(margen_bruto), 2) AS margen_bruto_usd,
    ROUND(
        SUM(margen_bruto) / NULLIF(SUM(venta_neta), 0),
        4
    ) AS margen_pct
FROM vw_ventas;
ventas_netas_usd margen_bruto_usd margen_pct
32825861.009038105.000.2753

El margen global es 27,53 %. El promedio simple de margen_pct por línea da 31,21 %. La diferencia aparece porque una línea pequeña y una línea grande reciben el mismo peso en AVG(margen_pct). El ratio de sumas conserva los importes que originan el indicador.

NULLIF(SUM(venta_neta), 0) devuelve NULL cuando el denominador es cero y evita una división inválida.

GROUP BY: cambiar el grano de salida

GROUP BY crea un grupo por cada combinación de dimensiones. Toda columna seleccionada fuera de una agregación debe identificar un grupo.

SELECT
    familia,
    COUNT(*) AS lineas,
    COUNT(DISTINCT pedido) AS pedidos,
    ROUND(SUM(venta_neta), 2) AS ventas_netas_usd,
    ROUND(SUM(margen_bruto), 2) AS margen_bruto_usd,
    ROUND(SUM(margen_bruto) / SUM(venta_neta), 4)
        AS margen_pct
FROM vw_ventas
GROUP BY familia
ORDER BY ventas_netas_usd DESC;

WHERE y HAVING

WHERE filtra filas antes de agrupar. HAVING filtra grupos después de calcular las agregaciones.

SELECT
    familia,
    ROUND(SUM(venta_neta), 2) AS ventas_netas_usd
FROM vw_ventas
GROUP BY familia
HAVING SUM(venta_neta) > 5000000
ORDER BY ventas_netas_usd DESC;
familia ventas_netas_usd
Bombas14588690.80
Repuestos13707691.25

El umbral actúa sobre el total de cada familia. Un filtro regional seguiría ubicado en WHERE porque define las filas que entran en esos totales.

CASE: crear categorías reproducibles

CASE traduce condiciones en una clasificación.

SELECT
    CASE
        WHEN descuento_pct = 0 THEN 'Sin descuento'
        WHEN descuento_pct <= 0.05 THEN 'Hasta 5 %'
        ELSE 'Más de 5 %'
    END AS banda_descuento,
    COUNT(*) AS lineas,
    ROUND(SUM(venta_neta), 2) AS ventas_netas_usd,
    ROUND(SUM(margen_bruto) / SUM(venta_neta), 4)
        AS margen_pct
FROM vw_ventas
GROUP BY banda_descuento
ORDER BY ventas_netas_usd DESC;
banda_descuento lineas ventas_netas_usd margen_pct
Más de 5 %327815479747.450.2566
Hasta 5 %348514795163.550.2893
Sin descuento7372550950.000.3081

Los umbrales expresan una decisión analítica. Su documentación debe indicar quién los definió y con qué propósito. La salida describe una asociación entre banda y margen; una afirmación causal requeriría otro diseño de análisis.

CTE y función de ventana: una consulta intermedia

Una Common Table Expression separa etapas con nombres. La función de ventana calcula sobre varias filas y conserva una fila por grupo.

WITH ventas_por_familia AS (
    SELECT
        familia,
        SUM(venta_neta) AS ventas_netas_usd
    FROM vw_ventas
    GROUP BY familia
)
SELECT
    familia,
    ROUND(ventas_netas_usd, 2) AS ventas_netas_usd,
    ROUND(
        100 * ventas_netas_usd
        / SUM(ventas_netas_usd) OVER (),
        2
    ) AS participacion_pct
FROM ventas_por_familia
ORDER BY ventas_netas_usd DESC;
familia ventas_netas_usd participacion_pct
Bombas14588690.8044.44
Repuestos13707691.2541.76
Kits de mantenimiento4529478.9513.80

La CTE produce una fila por familia. SUM(...) OVER () calcula el total sobre esas tres filas y permite obtener participación sin reducir la cantidad de filas de la salida.

DDL: crear estructuras para trabajar

DDL modifica el catálogo de la base. Este ejemplo crea una tabla temporal de objetivos:

CREATE TEMP TABLE objetivos_familia (
    familia VARCHAR PRIMARY KEY,
    objetivo_margen_pct DECIMAL(5, 4)
);

ALTER TABLE objetivos_familia
ADD COLUMN responsable VARCHAR;

Una tabla temporal queda asociada a la sesión. Resulta apropiada para ejercicios y etapas intermedias. Una tabla persistente permanece en el archivo de base y requiere decisiones de diseño, gobierno y ciclo de vida.

CREATE TABLE AS SELECT materializa el resultado de una consulta:

CREATE TEMP TABLE resumen_region AS
SELECT
    region,
    SUM(venta_neta) AS ventas_netas_usd
FROM vw_ventas
GROUP BY region;

DROP TABLE resumen_region; elimina la tabla del catálogo. La práctica usa objetos temporales para mantener acotado el riesgo de cambios.

DML y transacciones

DML cambia las filas de una tabla. Se practica sobre la tabla temporal:

INSERT INTO objetivos_familia (
    familia,
    objetivo_margen_pct,
    responsable
)
VALUES
    ('Bombas', 0.2500, 'Dirección comercial'),
    ('Repuestos', 0.3000, 'Gerencia de posventa');

Una transacción agrupa cambios:

BEGIN TRANSACTION;

UPDATE objetivos_familia
SET objetivo_margen_pct = 0.2600
WHERE familia = 'Bombas';

SELECT *
FROM objetivos_familia;

ROLLBACK;

ROLLBACK descarta los cambios de la transacción. COMMIT los confirma. Un UPDATE o DELETE requiere revisar el filtro con un SELECT previo y verificar cuántas filas serán afectadas.

DCL y permisos

En una plataforma multiusuario, DCL expresa qué rol puede acceder a cada objeto. Un patrón habitual es:

GRANT SELECT ON vw_ventas TO rol_analista;
REVOKE UPDATE ON vw_ventas FROM rol_analista;

La sintaxis exacta y las capacidades dependen del motor. El notebook local de DuckDB se concentra en archivos y sesiones individuales. Plataformas como PostgreSQL, SQL Server y los data warehouses cloud incorporan administración de roles y permisos como parte de su operación.

El principio de mínimo privilegio asigna las capacidades necesarias para una tarea concreta. Un perfil analítico suele recibir lectura sobre vistas curadas y permisos acotados para crear resultados en un espacio propio.

Orden escrito y orden lógico

La consulta se escribe con SELECT al comienzo. El razonamiento lógico sigue otra secuencia aproximada:

  1. FROM y relaciones;
  2. WHERE;
  3. GROUP BY;
  4. agregaciones;
  5. HAVING;
  6. SELECT;
  7. funciones de ventana;
  8. ORDER BY;
  9. LIMIT.

Esta secuencia explica por qué un alias creado en SELECT puede usarse en ORDER BY y suele quedar fuera del alcance de WHERE.

Cómo interpretar un resultado

Una salida permite describir patrones observados dentro del universo consultado:

Bombas representa 44,44 % de la venta neta del release y presenta un margen porcentual de 22,77 %.

La frase declara la fuente, el período y la métrica cuando forma parte de una entrega. Una recomendación comercial necesita sumar objetivos, capacidad, condiciones competitivas y riesgo. SQL aporta evidencia reproducible; la decisión integra esa evidencia con el contexto del negocio.

Auditoría de consultas y uso de IA

Una consulta sugerida por IA atraviesa el mismo control que una consulta escrita manualmente:

  1. identificar la fuente y el grano;
  2. comprobar nombres y tipos de campos;
  3. revisar filtros y límites temporales;
  4. verificar el tratamiento de NULL;
  5. ejecutar sobre un caso pequeño;
  6. contar filas y claves distintas;
  7. reconciliar una métrica;
  8. explicar cada cláusula;
  9. registrar los cambios hechos al borrador.

La entrega conserva cuatro piezas: pregunta, consulta ejecutada, control y lectura del resultado. Esa estructura permite revisar el razonamiento completo.
