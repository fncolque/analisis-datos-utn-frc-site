Para qué usamos Python en esta materia

Python permite leer datos, transformar tablas y dejar una secuencia de operaciones que otra persona puede ejecutar. En esta unidad retomamos las nociones introducidas en el primer laboratorio y las aplicamos de forma sistemática con Pandas. El objetivo consiste en comprender qué hace cada celda, anticipar su salida y verificar que la transformación preserve el significado de los datos.

El lenguaje ofrece muchas posibilidades fuera del análisis tabular. Aquí trabajaremos con el subconjunto necesario para inspeccionar un DataFrame, filtrar observaciones, crear columnas, agrupar y reconciliar resultados. Cuando aparezca una estructura nueva, la explicación se vinculará con la pregunta analítica que permite responder.

El notebook como documento ejecutable

Un notebook reúne texto, código y resultados en celdas. Las celdas de texto explican propósito, supuestos y conclusiones. Las de código leen archivos o realizan operaciones. La salida queda debajo de la celda y puede contener un valor, una tabla, un gráfico o un mensaje de error.

La sesión mantiene variables y archivos en memoria mientras el entorno permanece activo. Ese estado hace posible avanzar paso a paso, pero también puede ocultar dependencias. Una celda puede funcionar porque otra se ejecutó antes, aunque aparezca más abajo. Para comprobar reproducibilidad conviene reiniciar el entorno y utilizar “Ejecutar todas”. Si el recorrido falla desde una sesión limpia, falta una entrada, una instrucción o una dependencia explícita.

Antes de compartir, el notebook debe evitar secretos y datos que excedan el propósito de la actividad. También debe distinguir una salida guardada de una ejecución reciente: la presencia de una tabla en pantalla no garantiza que el código actual la produzca.

Variables, valores y tipos

Una variable asigna un nombre a un valor para reutilizarlo. El signo igual guarda el valor de la derecha bajo el nombre de la izquierda.

region_objetivo = "Patagonia"
umbral_demora = 5
tasa_otif = 0.82
incluir_parciales = True

Los tipos determinan qué operaciones tienen sentido. region_objetivo es texto; umbral_demora es un entero; tasa_otif es un número decimal; incluir_parciales expresa una condición booleana. Python distingue mayúsculas y minúsculas, por lo que Region_objetivo sería otro nombre.

Tipo Ejemplo Uso habitual
str"Patagonia"categorías, nombres y códigos
int5conteos o cantidades enteras
float0.82tasas e importes con decimales
boolTruecondiciones que pueden cumplirse o no
datetime2026-09-23fechas y horas luego de convertirlas

Una fecha recibida como texto conserva caracteres, pero todavía no permite calcular duraciones de manera confiable. El paso de conversión debe ser visible y controlar valores que no puedan interpretarse.

Funciones, métodos y argumentos

Una función recibe datos, ejecuta una operación y puede devolver un resultado. len(df) cuenta elementos del objeto entregado entre paréntesis. Un método es una función asociada a un objeto: df.head() le pide al DataFrame que muestre sus primeras filas.

cantidad_filas = len(df)
primeras_filas = df.head(5)
venta_total = df["net_sales_usd"].sum()

Los valores entre paréntesis son argumentos. En head(5), el número indica cuántas filas mostrar. Algunos argumentos tienen nombre y permiten leer la intención, como ascending=False al ordenar de mayor a menor.

Una llamada puede devolver un valor sin modificar la tabla original. Por eso asignamos el resultado a una variable cuando queremos conservarlo. Leer la documentación ayuda a reconocer qué recibe una función, qué devuelve y si modifica el objeto.

Condiciones y bucles

Una condición es una expresión que Python evalúa como verdadera o falsa. La palabra if permite ejecutar un bloque únicamente cuando la condición se cumple. Un bucle repite un bloque: for toma, de a uno, los elementos de una colección como una lista. La sangría indica qué instrucciones pertenecen al bloque, por lo que los espacios iniciales forman parte de la estructura del programa.

margenes = [0.24, 0.18, 0.31]

for margen in margenes:
    if margen < 0.20:
        print("revisar")
    else:
        print("ok")

La variable margen recibe un valor distinto en cada iteración. El bucle resulta útil para comprender la repetición y para resolver tareas que dependen del estado de cada paso. En una tabla, Pandas suele expresar filtros, columnas derivadas y agrupaciones como operaciones sobre el DataFrame completo. Esa forma tabular reduce el código que la persona debe administrar y vuelve más visible la transformación aplicada.

La tabla de Pandas se llama DataFrame

Un DataFrame representa datos tabulares mediante filas, columnas, un índice y un tipo por columna. Se parece a una hoja de cálculo, aunque sus operaciones se expresan como instrucciones reproducibles. El índice identifica la posición interna y no reemplaza las claves del negocio.

Pandas tampoco decide el grano por nosotros. Un DataFrame puede contener una fila por línea de pedido, por pedido o por cliente. Antes de sumar o contar debemos escribir qué representa una fila y qué columnas identifican esa observación.

Cuando leemos un CSV, Pandas infiere tipos a partir del contenido. Esa inferencia es un punto de partida. El notebook debe convertir fechas, importes o códigos según el contrato y registrar los valores que no cumplen la expectativa.

Inspeccionar antes de transformar

La primera lectura busca orientación. shape devuelve la cantidad de filas y columnas; head muestra ejemplos; info resume tipos y valores presentes; dtypes lista el tipo de cada columna; isna().sum() cuenta faltantes.

print(df.shape)
display(df.head())
df.info()
display(df.isna().sum().sort_values(ascending=False))

Estas salidas se leen en conjunto. Un archivo puede tener 900 filas y 15 columnas, pero necesitamos confirmar el grano, el rango temporal y las categorías antes de interpretar esa dimensión. Una columna numérica cargada como texto suele indicar símbolos, separadores o valores inválidos. Un faltante merece contexto: puede ser defecto, ausencia legítima o dato todavía no disponible.

Una inspección breve debería responder cuántas observaciones hay, qué representa cada una, qué tipos se infirieron, qué campos faltan y qué período cubre la fuente. Las respuestas forman la línea de base contra la que se compararán los pasos posteriores.

Seleccionar columnas y filtrar filas

Seleccionar columnas reduce el DataFrame a los campos necesarios para una pregunta. Los corchetes externos acceden a la tabla y la lista interna contiene los nombres elegidos.

columnas = ["order_date", "region", "net_sales_usd"]
vista = df[columnas]

Un filtro construye una serie de valores True y False y conserva las filas donde la condición es verdadera.

es_patagonia = df["region"] == "Patagonia"
patagonia = df[es_patagonia]

Al combinar condiciones, Pandas utiliza & para “y” y | para “o”. Cada comparación debe ir entre paréntesis. Después de filtrar conviene contar filas, revisar el rango temporal y confirmar categorías. El resultado representa una población nueva, por lo que la descripción del análisis debe señalar qué quedó incluido.

Crear una columna derivada

Una columna derivada expresa una regla mediante campos existentes. En Faro Sur, el margen bruto en dólares se obtiene al restar el costo total de la venta neta.

df["gross_margin_usd"] = (
    df["net_sales_usd"] - df["total_cost_usd"]
)

Antes de aceptar la salida comprobamos unidades y tipos. Ambos importes deben representar la misma moneda y el mismo grano. También revisamos faltantes y rangos inesperados. Si un costo falta, la resta producirá un valor ausente; reemplazarlo por cero cambiaría el significado y requiere una regla autorizada.

Una columna de porcentaje agrega otro riesgo: división por cero. La celda debe definir qué ocurre cuando el denominador es nulo o vale cero y comparar el resultado con casos conocidos.

Agrupar cambia el grano de salida

groupby reúne filas que comparten una o varias categorías. agg declara las métricas calculadas en cada grupo.

resumen = (
    df.groupby("region", as_index=False)
      .agg(
          venta_neta=("net_sales_usd", "sum"),
          pedidos=("order_id", "nunique")
      )
)

La fuente puede tener una fila por línea de pedido, mientras que resumen tendrá una fila por región. La venta es aditiva y se suma; los pedidos se cuentan de manera distinta porque order_id se repite en varias líneas. Usar count sobre esa columna contaría líneas, no pedidos.

Una lectura clara sigue cuatro preguntas: cuál es la fuente, qué columnas forman los grupos, cómo se calcula cada métrica y qué representa una fila de salida. Este contrato permite comparar el resultado con una consulta SQL equivalente.

Separar pasos para poder controlarlos

Un pipeline puede escribirse como varias asignaciones legibles. Cada variable representa un estado intermedio y facilita observar conteos.

filtrado = df[df["order_date"] >= "2026-01-01"]

resumen = (
    filtrado.groupby("region", as_index=False)["net_sales_usd"]
            .sum()
)

ordenado = resumen.sort_values("net_sales_usd", ascending=False)

El encadenamiento reduce líneas, pero una secuencia demasiado compacta puede esconder el punto donde cambió la población. Durante el aprendizaje conviene separar filtros, agrupaciones y ordenamientos. Después de comprenderlos, pueden combinarse manteniendo nombres y controles que hagan visible la intención.

El análisis exploratorio formula mejores preguntas

El análisis exploratorio de datos, o EDA, examina estructura, calidad, distribución, segmentos, anomalías y relaciones antes de construir una conclusión. Su propósito es conocer qué puede sostener la fuente y detectar supuestos que deben revisarse.

Una exploración de demora puede comenzar con conteos y faltantes, continuar con mediana y percentiles, comparar regiones y observar valores extremos. Cada salida abre una pregunta. Si Patagonia muestra una demora mayor, podemos revisar distancia, transportista, disponibilidad o composición de pedidos. La observación todavía no demuestra cuál de esos factores explica el patrón.

El notebook debe registrar el período, la población y los filtros de cada resultado. Explorar muchas combinaciones sin documentarlas aumenta el riesgo de elegir una coincidencia atractiva. La pregunta de decisión mantiene el foco y ayuda a diferenciar hallazgos útiles de curiosidades.

Interpretar faltantes y valores extremos

Un faltante puede indicar un error de captura, una condición que no aplica, información todavía no disponible o un dato oculto por política. El tratamiento comienza por conocer la causa. Excluir, completar o marcar producen poblaciones diferentes y deben compararse.

Un valor extremo también admite varias interpretaciones. Puede ser una unidad equivocada, un evento raro válido o un cambio real del proceso. Por ejemplo, una demora de 120 días merece revisar pedido, fechas y fuente; eliminarla automáticamente borraría evidencia de un caso potencialmente relevante.

La exploración puede mostrar resultados con y sin casos extremos para evaluar sensibilidad. La decisión final conserva el registro original y explica el criterio aplicado.

Reconciliar Python con SQL

Si SQL y Pandas aplican la misma fuente, población y definición, deberían producir resultados compatibles. Una diferencia orienta la depuración hacia tipos de fecha, valores nulos, duplicados, redondeo, filtros o grano.

La comparación comienza con conteos simples: filas, claves distintas y rango temporal. Luego revisa totales aditivos y finalmente ratios. Para un porcentaje, conviene reconciliar numerador y denominador por separado. Dos ratios pueden coincidir por casualidad aunque ambas partes sean incorrectas.

La coincidencia demuestra consistencia de implementación dentro del alcance revisado. La interpretación del resultado sigue necesitando contexto y no convierte una asociación en causa.

Leer un error como información

Un mensaje de error identifica el tipo de problema y suele señalar la línea que lo produjo. Comparar una fecha de texto con un datetime, escribir = donde corresponde == o usar un nombre de columna inexistente son errores frecuentes durante las primeras prácticas.

El procedimiento consiste en leer el último mensaje, ubicar la operación, observar los tipos y aplicar el cambio mínimo. Luego se ejecuta la celda y se comprueba la salida. Cambiar varias líneas al mismo tiempo dificulta saber qué corrección resolvió el problema.

Algunos errores no detienen la ejecución. Promediar porcentajes o sumar una columna cargada como texto puede producir una salida plausible. Los controles de grano, tipo y rango ayudan a detectar estos problemas semánticos.

Revisar código sugerido por inteligencia artificial

Un asistente puede explicar una función, proponer una transformación o ayudar a interpretar un error. Una respuesta útil identifica la línea, explica los tipos y el grano, propone un cambio acotado y anticipa una forma de control.

El estudiante o equipo ejecuta la propuesta sobre su propia copia y compara la salida con el contrato. También revisa que los nombres de columnas existan y que ningún dato sensible se haya enviado a un servicio externo. El registro distingue la sugerencia de la decisión adoptada.

Pedir una solución completa sin comprenderla reduce la capacidad de depurar. Pedir que el asistente explique una expresión y luego modificar un filtro conocido convierte la interacción en una oportunidad de aprendizaje verificable.

  3. ¿Qué representa la serie booleana creada por un filtro?
  4. ¿Qué grano produce la agrupación por región?
  5. ¿Por qué conviene reconciliar el numerador y el denominador de un ratio?
  6. ¿Qué evidencia permite decidir si un outlier es un error?
