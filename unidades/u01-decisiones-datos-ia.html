Glosario para empezar

Conceptos técnicos, en lenguaje de negocio.

01

Pipeline

Es la secuencia organizada de pasos que lleva un dato desde su origen hasta una respuesta utilizable. Permite reconstruir el origen de un resultado y los controles que atravesó.

Registro→Tabla→Métrica→Decisión
02

SQL

Lenguaje para hacer preguntas estructuradas a una base de datos. Permite filtrar y agrupar información; también relaciona tablas. Su aplicación forma parte de la unidad 3.

03

Python

Lenguaje de programación de propósito general. En la materia aprenderemos a leer y adaptar notebooks preparados para explorar y controlar datos.

04

Formatos de datos

CSV organiza una tabla; JSON representa estructuras más flexibles; Parquet optimiza análisis a escala. Elegir formato también es una decisión técnica.

05

KPI

Indicador clave de desempeño. Su definición incluye fórmula, unidad, grano, frecuencia, dueño y decisión asociada.

06

IA en análisis

Puede explorar, explicar, generar código y comunicar. El equipo ejecuta el resultado, lo compara con la fuente, documenta los cambios y explica la salida.

El análisis comienza con una decisión

Un dato es una representación registrada de un hecho, estado o evento. Por sí solo no indica qué hacer. En la materia se utilizará la siguiente cadena:

registro → dato contextualizado → evidencia → interpretación → decisión → acción → aprendizaje
  • Registro: valor capturado por un sistema, formulario, sensor o persona.
  • Dato contextualizado: registro con definición, unidad, tiempo, origen y grano.
  • Evidencia: conjunto de datos y controles relevantes para una pregunta.
  • Interpretación: significado propuesto, condicionado por conocimiento del negocio.
  • Decisión: elección entre alternativas bajo restricciones.
  • Acción: intervención ejecutada.
  • Aprendizaje: comparación entre resultado esperado y observado.

El pipeline analítico es el sistema que hace posible esa cadena. La tecnología reduce costo, tiempo o riesgo. La formulación de la decisión permanece a cargo de las personas responsables del proceso.

Datos como ventaja competitiva

Los datos pueden crear ventaja cuando una organización logra un ciclo difícil de imitar:

  1. captura señales relevantes antes o con mayor calidad;
  2. las combina con conocimiento del proceso;
  3. decide con menor demora o incertidumbre;
  4. incorpora la decisión a una operación;
  5. observa el resultado y mejora.

El activo combina:

  • datos confiables;
  • definiciones compartidas;
  • infraestructura proporcional;
  • capacidades humanas;
  • permisos y gobierno;
  • procesos capaces de actuar.

Los datos también tienen costos: captura, almacenamiento, integración, seguridad, errores, mantenimiento y exposición legal. Acumular información “por si acaso” puede crear deuda y riesgo.

Ejemplo industrial

Conocer el stock disponible no mejora el servicio si:

  • se actualiza después de prometer la fecha;
  • las reservas no están incluidas;
  • cada depósito define “disponible” de forma distinta;
  • nadie tiene autoridad para reponer o reasignar.

La ventaja surge del circuito operativo que vuelve accionable el número.

Decisión, audiencia y KPI

Una decisión debe identificar:

  • responsable: quién puede actuar;
  • objeto: sobre qué se decide;
  • alternativas: qué opciones existen;
  • horizonte: cuándo debe decidirse;
  • restricciones: costo, capacidad, servicio, riesgo;
  • criterio: cómo se compara una alternativa.

Un KPI es un indicador ligado a un objetivo. No todo número visible es un KPI.

Definición completa

Para evitar ambigüedad se documentan:

  • nombre;
  • propósito;
  • numerador y denominador;
  • unidad;
  • grano;
  • fecha utilizada;
  • filtros;
  • frecuencia;
  • dueño;
  • comportamiento esperado;
  • acciones posibles.

Incentivos y efectos no deseados

Optimizar un KPI aislado puede empeorar el sistema:

  • maximizar ventas puede reducir margen;
  • minimizar inventario puede empeorar nivel de servicio;
  • maximizar entregas “a tiempo” puede incentivar promesas conservadoras;
  • reducir costo logístico puede aumentar demoras.

Por eso la materia usa métricas como lentes, no como objetivos automáticos.

IA integrada al proceso

Se distinguen dos ideas:

  • IA analítica: modelos que clasifican, predicen, recomiendan o detectan patrones;
  • IA generativa: sistemas que producen texto, código, imágenes u otras salidas a partir de instrucciones y contexto.

En 2026 la IA se incorpora transversalmente:

La evidencia requiere fuentes y controles. Una respuesta puede sonar convincente y contener errores por:

  • datos de entrenamiento incompletos;
  • contexto insuficiente;
  • ambigüedad;
  • cálculo no ejecutado;
  • fuente inventada;
  • mezcla de granos;
  • sesgo de confirmación del usuario.

Responsabilidad humana

El profesional sigue siendo responsable de:

  • definir qué se intenta decidir;
  • autorizar datos y permisos;
  • comprobar fuentes;
  • ejecutar cálculos;
  • evaluar materialidad;
  • declarar límites;
  • decidir cuándo no automatizar;
  • explicar consecuencias.

La trazabilidad del uso de IA permite saber qué fue propuesto, qué se verificó y qué se corrigió.

Faro Sur como sistema de decisiones

Faro Sur presenta tres tensiones:

  1. ventas crecientes con margen rezagado;
  2. pedidos tardíos o incompletos;
  3. faltantes y acumulación de inventario.

Una tabla de líneas de pedido permite analizar ventas y margen. Otras fuentes resultan necesarias para explicar:

  • disponibilidad al prometer;
  • entregas parciales;
  • capacidad productiva;
  • demoras de transporte;
  • cobranza;
  • causas de un faltante.

El primer aprendizaje es reconocer qué pregunta permite una fuente y cuál no.

Distinciones que deben quedar claras

  • el dato representa un hecho y la decisión selecciona una acción;
  • la correlación describe asociación y la causalidad exige evidencia adicional;
  • el promedio resume el centro y la distribución muestra dispersión y extremos;
  • una métrica ilumina una parte del objetivo;
  • un dashboard organiza señales y el insight agrega interpretación relevante;
  • la IA genera o evalúa propuestas y la base de datos conserva registros consultables;
  • la validez depende de definiciones, fuentes y controles además de la precisión numérica;
  • una buena definición orienta el uso del volumen disponible.

Preguntas de comprobación

  1. ¿Qué representa una fila de ventas_inicial.csv?
  2. ¿Qué fecha usaría para medir demanda y cuál para medir servicio?
  3. ¿Puede una mayor venta neta producir menor margen porcentual?
  4. ¿Qué acción concreta cambiaría al conocer OTIF?
  5. ¿Cómo verificaría una consulta propuesta por IA?
  6. ¿Qué dato no debería cargarse en una herramienta externa?

Protocolo mínimo de IA

Toda respuesta necesita verificación.

  1. Caso¿La respuesta coincide con la pregunta?
  2. Grano¿Respeta qué representa cada fila?
  3. Cálculo¿Se ejecutó sobre la fuente correcta?
  4. Control¿Reconciliamos el resultado?

Regla: ejecutar + comparar con la fuente + documentar + explicar.
